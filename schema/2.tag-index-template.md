**结构**: 按"党建 → 业务 → 治理"三大模块组织

## 标签使用说明

1. **组合使用**：标签可自由组合，如 `#党建与纪检监察 #干部选育管用` 表示党建工作中的干部管理
2. **层级对应**：一级标签概括工作领域，二级标签细化具体事务
3. **按需取用**：根据实际内容选择相关标签，不必全部使用
4. **动态更新**：可根据工作需要新增或调整标签

## 标签增长机制

**铁律**: 标签必须来自标签字典，但字典本身可按需增长。

### 提案流程

```
AI 摄入时发现现有标签无法覆盖内容
        ↓
在页面的 open-questions 字段中提案
        ↓
人工审核（用户决定是否采纳）
        ↓
采纳 → 更新字典 + 升级版本号
拒绝 → AI 改用最接近的现有标签
```

### 提案格式

在 wiki 页面的 frontmatter 中：

```yaml
open-questions:
  - "tag-proposal: #新标签名 | 一级/二级 | 说明 | 理由：现有[xxx]无法覆盖[具体场景]"
```

### 审核标准

| 标准 | 说明 |
|------|------|
| 不重复 | 新标签不与现有标签重复或高度重叠 |
| 有体量 | 覆盖场景预计有 3 个以上页面会使用 |
| 合结构 | 符合领域模块结构 |
| 可定位 | 标签名明确指向具体工作领域 |

### 版本更新

标签字典每次修改后：
- `version` 升级
- `last-updated` 更新为当日
- 在 `wiki/log.md` 中记录变更

## 适配其他领域

将本模板用于其他领域时，只需：

1. **修改模块划分**（如：产品 → 技术 → 运营）
2. **替换一级标签**（保留 8-15 个为宜）
3. **调整二级标签**（每个一级标签下 5-12 个）

关键是保持三层结构（模块→一级标签→二级标签）不变。
