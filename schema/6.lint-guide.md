# 健康检查规范（Knowledge-LINT v1.1）

> **定位**: "健康检查"触发词下的执行标准。知识库从内容体检升级为**五层体系（L0-L4）**体检：内容正确性（L0）+ 工作流资产一致性（L1）+ 画像质量（L2）+ 写作产出一致性（L3）+ 元数据导航（L4）。
> **演进动因**: 知识库引入"范式×画像"写作体系后，范式页、人物画像、触发映射、反哺日志成为一级资产——内容层查不出它们的失配/停摆（2026-08-16 实测：顾明远画像已补强但 schema/4、schema/5 仍标"雏形"；speech-comparison-log 为空；index 7 条 WAIC 链接断链）。
> **上游**: CLAUDE.md §三-A（入口）；`schema/3.structured-learning.md`（内容层方法）；`schema/4.writing-guide.md` §五（闭环A/B/C）；`schema/5.persona-guide.md`（画像标准）。

---

## 一、检查频率与范围

| 模式 | 频率 | 覆盖层 | 场景 |
|------|------|--------|------|
| **快检** | 每月（或每次"健康检查"触发） | L0 + L1 | 常规维护，自动项为主 |
| **深检** | 每季（或重大重构后） | L0 - L4 | 全量体检，含人工抽样 |

> 触发词"健康检查"默认走**快检**；如需深检，用户可指定"深度健康检查"。

## 二、五层检查清单（L0-L4）

### L0 内容层（保留，来自 CLAUDE.md §三-A）

| # | 检查项 | 方式 | 命令/要点 |
|---|--------|------|----------|
| L0-1 | 矛盾检测 | 自动+人工 | 跨页对比同一主题主张（顾明远观点、会议日期、数据指标等） |
| L0-2 | 时效检测 | 自动 | `grep last-updated`，超60天页面对照最新来源 |
| L0-3 | 孤立检测 | 自动 | 无入链页面（注意 `[[人物-X\|X]]` 表格转义管道、短名前缀匹配的误报） |
| L0-4 | 缺口检测 | 人工 | 重要但缺失的概念页 |

### L1 工作流资产层（范式/画像/映射的静态一致性）`新增`

| # | 检查项 | 方式 | 检查要点 |
|---|--------|------|----------|
| L1-1 | 画像状态三方对齐 | 自动+人工 | `schema/4` §四 画像库表 ↔ `schema/5` §六 画像库表 ↔ `wiki/entities/人物-XX.md` 实际状态，三方必须一致（状态值：完整画像/已补强/雏形/基本信息） |
| L1-2 | 范式库完整性 | 自动 | 4x 范式页 ↔ `4.writing-guide` §一 路由表 ↔ `schema/0.index` 登记 ↔ synthesis 实际产出体裁，四向核对 |
| L1-3 | 触发映射同步 | 自动 | CLAUDE.md §一 触发词表 ↔ 4x 范式页 ↔ 默认画像，新增范式/画像后是否都登记 |
| L1-4 | tag-proposal 提案积压 | 自动 | Grep 全库 `tag-proposal:`，列出待人工审核的提案（采纳→注册进 tag-index 升版本；拒绝→删除提案） |

### L2 画像质量层（画像资产的完整性/全面性/一致性）`新增`

| # | 检查项 | 方式 | 检查要点 |
|---|--------|------|----------|
| L2-1 | 画像 7 维完整性 | 人工 | 已建画像是否填满 schema/5 的 7 维模板；缺维标注（"待补强"） |
| L2-2 | 画像升级机会检测 | 自动 | 扫描"基本信息"状态人物页是否有 ≥2 篇新材料却未升级画像（达到升级阈值） |
| L2-3 | 画像时效性 | 自动 | 画像 last-updated 超期（>60天）→ 对照 raw 中该人物新文稿，提示反哺 |
| L2-4 | 画像-源材料一致性 | 人工抽样 | 画像"典型表述库/核心理念" ↔ 人物页"核心观点" ↔ 最新摄入材料，防画像与源脱节 |

### L3 写作产出层（范式×画像组合的动态一致性）`新增`

| # | 检查项 | 方式 | 检查要点 |
|---|--------|------|----------|
| L3-1 | 范式-产出一致性 | 人工抽样 | 最新 synthesis 稿（第一议题/评论）是否遵循对应 4x 范式结构；范式是否已随产出演进但未同步 |
| L3-2 | 画像-产出一致性 | 人工抽样 | 以指定画像写的稿"像他说话"程度复检（从 synthesis 反查画像覆盖度） |
| L3-3 | 反哺闭环执行审计 | 自动 | 闭环A触发后 `wiki/speech-comparison-log.md` 是否实际追加（"一次一记"）；为空 → 排查引导缺失/机制停摆 |
| L3-4 | 引文纪律审计 | 人工抽样 | synthesis 稿是否遵守 CLAUDE.md §九「引文纪律」六条：数据可溯源（无源数据即废）/加引号=原文照录/限定条件保留/跨场合语境标注/转引标注/政策归属准确 |
| L3-5 | 去AI味审计 | 人工抽样 | synthesis 稿是否过 schema/4 §三-A 清单：正文破折号清零/句式去模板/动词去同质化/意象词收敛/升华腔克制/引号节制 |

### L4 元数据与导航层（基础设施健康）`新增`

| # | 检查项 | 方式 | 检查要点 |
|---|--------|------|----------|
| L4-1 | 统计信息对齐 | 自动 | index.md 统计区（标签版本号/页面数/画像库）↔ schema 实际版本 |
| L4-2 | 索引断链检测 | 自动 | index.md 全部 `[[链接]]` ↔ 实际文件名（注意短名/长名不一致，如 WAIC 纪要 `-v1.0-2026-08-11` 后缀） |
| L4-3 | 工作流文件可发现性 | 自动 | `wiki/speech-comparison-log.md` / `wiki/open-questions.md` 等基础设施是否有导航入口 |
| L4-4 | 页面规模监控 | 自动 | 超 300 行软上限页面清单（GUIDELINE），标出超限最严重的拆分候选 |

## 三、自动项检测命令速查

```bash
# L0-2 时效：超60天页面
grep -rln "last-updated: 2026-0[1-5]\|last-updated: 2026-06-0[1-9]\|last-updated: 2026-06-1[0-6]" wiki/ --include="*.md"

# L0-3 孤立：无入链页面（脚本需处理 [[人物-X\|X]] 转义管道 + 短名前缀匹配）
# （无现成脚本，按本规范手写 python 脚本；实现风格可参考 .claude/sync-log.py）

# L1-1 画像状态三方对齐：对比 schema/4 §四、schema/5 §六 与各人物页
grep -n "雏形\|已补强\|完整画像\|基本信息" schema/4.writing-guide.md schema/5.persona-guide.md

# L1-4 提案积压：待审核 tag-proposal
grep -rn "tag-proposal:" wiki/ --include="*.md"

# L2-3 画像时效：人物页超期
grep -rln "last-updated: 2026-0[1-5]\|last-updated: 2026-06-0[1-9]\|last-updated: 2026-06-1[0-6]" wiki/entities/人物-*.md

# L3-3 反哺闭环审计：对比日志是否空
grep -c "## \[" wiki/speech-comparison-log.md

# L4-2 索引断链：index 链接 vs 实际文件名
# （对比 [[链接]] 目标与 wiki/ 下实际 .md 文件名，排除 schema/ 引用）

# L4-4 页面规模：超300行
find wiki -name "*.md" -not -name "log-*" | while read f; do l=$(wc -l < "$f"); [ "$l" -gt 300 ] && echo "$f ($l 行)"; done | sort
```

## 四、报告模板

健康检查输出按**三层分级**，与 CLAUDE.md 优先级体系同构：

```
## 健康检查报告（日期）

### 🔴 高优先级（自动项可执行修复）
[断链、状态表失配、空日志等——可直接修复，修复后更新 log.md]

### 🟡 中优先级（需人工判断）
[画像一致性、范式产出一致性、超限页拆分、时效页更新——给出候选，用户确认后执行]

### ⚪ 提案建议（增长机会）
[新画像候选（L2-2）、新范式候选（L1-2）、tag-proposal 采纳建议（L1-4）]

### ✅ 已核查正常项
[明确声明哪些维度查过且正常——防"未查即报健康"]
```

### 报告纪律 `IMPORTANT`
- **区分误报与真问题**：自动脚本需注意三大误报源——①正文/主题里的 `#`（非 frontmatter tags）②`[[人物-X\|X]]` 表格转义管道 ③index 短名链接（可能只是"短名可达"而非断链）。报告前必须人工复核，不得把误报当问题汇报。
- **不查即报=失职**：每层检查需在"✅正常项"中声明已覆盖；未执行的维度明确标注"未覆盖"。
- **修复闭环**：`[自动]` 项修复后必须回写 `wiki/log.md`；`[人工]` 项待用户确认后执行。

## 五、与上游流程的关系

- 内容层（L0）沿用 CLAUDE.md §三-A 五步流程
- 工作流资产层（L1/L2/L3）衔接 `schema/4.writing-guide.md` §五 闭环 A/B/C：
  - 闭环C（定期复核）明细化 = L1-1 + L2-3 + L3-1/L3-2
  - 闭环A 执行审计 = L3-3
- 画像标准以 `schema/5.persona-guide.md` 为权威；状态值（完整画像/已补强/雏形/基本信息）应全库统一，作为 L1-1 对齐基准
