# 结构化学习法

> **定位**: Knowledge-IN 流程的核心执行标准。分两级：先选提取方法（怎么学），再定存储策略（存哪里）。v4.1 新增对比模式（修改痕迹反向建模）。

---

## 文件类型 → 路由速查

| 来源目录 | 文件类型 | 提取方法 | 存储位置 |
|---------|---------|---------|---------|
| raw/policy/ | 上级政策 | 政策学习法 | wiki/concepts/ |
| raw/documents/ / raw/practice/ | 内部文件 | 政策学习法 | 三层分流（见第二篇） |
| raw/sources/（案例） | 典型案例 | 案例拆解法 | wiki/entities/ + wiki/concepts/ |

# 第一篇：提取方法

> 根据文件类型选择对应的提取方法。四种方法互斥，一次只选一种。

---

## 一、政策学习法

**适用**: raw/policy/（上级政策）、raw/documents/、raw/practice/（内部文件、报告、讲话）

**目标**: 上级政策 → 知导向、明底线、抓重点、转行动；内部文件 → 存史实、备调用

### 5 步流程

**Step 1 — 抓总**: 总体思路 + 核心目标 + 关键词体系

```
**总体思路**: [原文关键表述]
**核心目标**: [量化 + 定性]
**关键词体系**: [关键词1, 关键词2, ...]
```

> **奋斗目标/展望表述 — 重点提取**: 政策文件中"为...努力奋斗""加快构建...""奋力推进...""全面建设...""着力打造..."等展望性语句，往往是发展目标和方向的凝练概括。此类表述**全文照录**，不简化。

```
**奋斗目标**: [原文展望/号召性表述，全文照录]
```

> **制度定位表述 — 强制收录**: 政策文件中"把...作为...""把...放在...""以...为..."等句式，表达的是"什么等于什么"的根本判断——制度定位、根本标准、核心关系，是政策逻辑的骨架。**必须全文照录，附条文编号**，不可简化为要点概括。

```
**制度定位（原文照录）**:
> **（第X条）** 把[对象]作为/放在[定位]，......
```

**搜索方法**: 在源文件中检索 `把.*作为`、`把.*放在`、`以.*为` 等正则模式。
**存储位置**: 在概念页的对应制度板块开头，以"制度定位（原文照录）"或"根本定位（原文照录）"子标题呈现。

**Step 2 — 拆块**: 按文件内在逻辑拆分为板块，标注关系（并列/递进/从属）

**Step 3 — 逐条提炼**: 保留原文动词 + 责任单位 + 数据指标

```
| 序号 | 核心要点 | 责任单位 | 关键词 |
|------|---------|---------|--------|
| 1 | [原文关键表述，含动词] | [单位] | [关键词] |
```

**Step 4 — 主要精华**: 要点表 / 金词库 / 可复用材料 / 关联更新

**Step 5 — 行动清单**（上级政策专属，内部文件可跳过）:

```
行动清单:
  1. [具体行动] — 时限：[短期/中期/长期]
```

### 动词保留
必须保留：实施、推进、开展、强化、完善、力争、实现、达到、确保、完成
效果动词：形成、构建、打造、完成
禁止：替换为弱动词（"做""搞""抓"）

### 政策学习法降级路径

| 场景 | 主方案 | 降级方案 |
|------|--------|---------|
| 文件过长(>500行) | 5步完整流程 | 抓总→拆块→选重点板块提炼，其余概述 |
| 文件缺少条款编号 | 制度定位附条文编号 | 标注"原文无条款编号"，以段落位置代替 |
| 无责任单位/数据指标 | 保留原文动词+数据 | 标注"原文未明确责任单位/量化指标" |

### 禁止事项
- ❌ 简化政策表述（原文引用，不失真）
- ❌ 遗漏责任单位和数据指标
- ❌ "幻想"（捏造不在原文中的表述）

## 二、案例拆解法

**适用**: raw/sources/ 下的典型案例

**目标**: 学思路、借举措、拓视野 → "他们怎么思考问题、怎么解决问题"

### 四问拆解

```
[问1] 背景与问题：他们面对什么困境/挑战？为什么需要解决？
[问2] 解题思路：他们怎么分析问题？核心逻辑是什么？
[问3] 关键举措：具体做了什么？（闪光点的集中地，原文照录）
[问4] 成效与启示：结果如何？对我们有什么可借鉴的？
```

### 双写规则

案例材料**同时写入两个位置**：

| 写入位置 | 内容 | 格式 |
|---------|------|------|
| wiki/entities/机构-XX大学.md | 机构简述 + 特色标签 | 简要条目 |
| wiki/concepts/对应概念页 | 具体举措 + 可借鉴点 | 新增"他校实践"板块 |

**概念页中的"他校实践"板块格式**:
```
## 他校实践

### [机构名] — [经验主题]
- **背景**: [一句话]
- **举措**: [关键做法，3-5条]
- **可借鉴**: [对我们的启示]
```

### 案例拆解法降级路径

| 场景 | 主方案 | 降级方案 |
|------|--------|---------|
| 案例信息不全（缺背景/缺成效） | 四问完整拆解 | 已有信息正常提取，缺失字段标注"原文未提供" |
| 案例无法确定对应概念页 | 双写 entities + concepts | 先写 entities，在 open-questions 提案概念页归属 |

### 禁止事项
- ❌ 将他校经验混淆为内部做法
- ❌ 只存实体页不写概念页（信息孤岛）
- ❌ 架空举措（不提取具体做法）

## 三、观点萃取法

**适用**: raw/sources/ 或 raw/research/ 下的学术文章、专家访谈

**目标**: 看趋势、预判方向 → 提取前瞻性判断

### 3 步流程

**Step 1 — 抓核心观点**: 作者的核心判断（1-3 条，原文引用）

```
核心观点:
  1. "[原文关键判断]"
```

**Step 2 — 列关键论据**: 支撑观点的数据/事实/逻辑

**Step 3 — 判趋势信号**: 指向什么变化？对实务意味着什么？

```
趋势信号:
  - 政策方向：[预判]
  - 实务影响：[对实务的启示]
```

### 写入位置

`wiki/concepts/对应概念页`，新增"前沿观点"板块：

```
## 前沿观点

> 来源：[文章/访谈名]，[作者]，[日期]

**核心判断**: [原文引用]

**趋势信号**: [对实务的启示]
```

### 观点萃取法降级路径 `IMPORTANT`

| 场景 | 主方案 | 降级方案 |
|------|--------|---------|
| 文章无明确核心判断 | 提取核心观点（原文引用） | 从论证逻辑中归纳，标注"归纳自原文论证"，不编造原文不存在的判断 |
| 文章缺数据支撑 | 列出关键论据（含数据） | 列出逻辑论据（无数据时），标注"原文未提供量化数据" |
| 趋势信号不明确 | 判趋势信号（政策+实务） | 注明"该文趋势信号不明确"，仅提取核心观点 |
| 多篇文章观点冲突 | 分别提取，标注冲突 | 在概念页中并置两种观点，标注"观点分歧"，不自行判定对错 |

### 禁止事项
- `HARD LIMIT` ❌ 混淆作者观点与政策规定（观点≠政策）
- `IMPORTANT` ❌ 将趋势预判当作既定事实
- `IMPORTANT` ❌ 在观点冲突时自行判定对错（应并置标注"观点分歧"）

## 四、对比模式 `CRITICAL`

**适用**: 特定作者/决策者的稿件（讲话、表态发言等），且 `wiki/synthesis/` 中存在同主题我方撰写的稿件

**触发方式**:
1. **自动触发**：Knowledge-IN Step 4 检测到文件同时满足「特定作者」+「存在同主题 synthesis 稿件」→ 自动切入对比模式
2. **手动触发**：用户输入"对比分析" → 直接执行对比模式

**目标**: 通过我方初稿与决策者终稿的增/删/改差异，反向推演决策者的关注热点、知识体系、思维角度和语言风格。**修改痕迹的信号强度高于公开讲话**——每次增/删/改都是决策者的主动选择。

> **领域适配**：对比模式的具体参数（作者识别、画像文件、写作指引）因领域而异。参考 `schema/4.domain-extension-example.md` 了解如何为特定领域配置对比模式。

### C1 — 识别对应稿件

```
□ 确认目标文件作者为特定决策者
□ 在 wiki/synthesis/ 中搜索同主题稿件（按主题关键词匹配）
□ 匹配成功 → 进入 C2
□ 匹配失败 → 进入降级决策树：
```

**C1 降级决策树** `CRITICAL`：

| 场景 | 条件 | 降级动作 |
|------|------|---------|
| C1-D1 零匹配 | 无任何 synthesis 稿件匹配 | 回退到「政策学习法（内部文件→事件层）」 |
| C1-D2 多匹配 | 2 个以上 synthesis 稿件候选 | 列出所有候选，用户选择 1 个进入 C2 |
| C1-D3 模糊匹配 | 仅有部分关键词匹配 | 展示匹配摘要，用户确认是否进入对比；否则降为 C1-D1 |
| C1-D4 版本过旧 | synthesis 距讲话日期 > 30 天 | 提示降级为普通入库（政策学习法），用户可强制进入对比 |
| C1-D5 内容不同 | 稿件围绕不同主题 | 走对比模式但 C2 增加"主题差异"维度 |

### C2 — A-F 六维对比

| 维度 | 分析内容 | 信号强度 |
|------|---------|---------|
| **A. 新增** | 决策者新增了什么话题/任务/案例/对标信息 | 高——直接揭示知识领域和关注热点 |
| **B. 删除** | 决策者删除了我们写的什么内容 | 高——负向信号，揭示什么不重要/不合适 |
| **C. 重写** | 同一话题角度如何调整（从什么角度→什么角度） | 高——揭示思维框架 |
| **D. 语言** | 句式、篇幅、修辞、程序性用语 | 中——揭示风格偏好 |
| **E. 知识引用** | 引用了哪些我们不掌握的信息 | 高——揭示知识体系边界 |
| **F. 场合适配** | 不同场合（决策会/学习会/调研）的差异 | 中——建立场合-文体映射 |

### C3 — 知识分流 `CRITICAL`

> **C3 知识分流是对比模式的专属存储步骤，替代 Knowledge-IN Step 5（存储）。对比模式走完 C1-C6 后，直接进入 Step 6（更新记录），跳过 Step 5。**

> `CRITICAL` 对比发现的实质内容必须分流写入知识库，不做热词堆砌。

### 对比写入清单（合并 C3 + C4）

> 按文件分组，每个文件一次性写入所有本次相关内容。以下为通用模板，具体文件名因领域而异。

```
□ wiki/comparison-log.md                   ← 追加原始证据（含 C5 总体判断）
□ wiki/entities/机构-{名称}.md              ← 战略目标/任务体系更新
□ wiki/entities/机构-XX.md（按需）           ← 对标机构信息
□ wiki/concepts/XX.md（按需）               ← 新概念/提法 → 触发 tag-index.md §标签增长机制 提案流程
□ wiki/entities/画像-{决策者}.md             ← 认知特征 + 注意力分配更新
□ schema/4.{domain}-extension.md           ← 偏好更新 + 热点更新 + 假设追踪 + 模板更新
□ wiki/entities/人物-{决策者}.md            ← 写作偏好通过指针引用领域扩展 schema（不重复写入）
```

### C5 — 输出总体判断

每次对比必须输出以下五个维度的总体判断：

| 结论维度 | 含义 | 后续应用 |
|---------|------|---------|
| **采纳程度** | 我们的内容有多少进入终稿 | 校准自信心：哪些板块已成熟 |
| **最大差异** | 结构性新增/删除 | 识别本次最需要关注的变化 |
| **策略变化** | 同一话题的角度偏移 | 直接指导下次同类稿件的切入点 |
| **受众适配** | 场合适配性调整 | 更新场合-文体映射表 |
| **删除性质判断** | "否定"还是"场合适配性删除" | 避免误读决策者意图 |

### C6 — 回链更新 `CRITICAL`

> 对比完成后必须反向更新被对比的 synthesis 稿件和相关页面的 frontmatter。

```
□ wiki/synthesis/ 被对比稿件 frontmatter:
    - 新增 compared-with: "[[raw/case-studies/文件名]]"
    - 更新 last-updated 为本日
□ wiki/entities/人物-{决策者}.md: 更新 last-updated
□ wiki/entities/机构-{名称}.md: 更新 last-updated（如有内容变更）
□ wiki/log.md: 追加对比操作摘要行
    - 格式: ## [YYYY-MM-DD] comparison | 第N次对比：[简述] | [[comparison-log#对应章节]]
```

### 对比模式禁止事项

- `CRITICAL` ❌ 对比发现仅记录不写入知识库（信息孤岛，后续无法检索）
- `IMPORTANT` ❌ 将场合适配性删除误判为决策者否定该内容
- `IMPORTANT` ❌ 单次对比发现直接标记为"已确认偏好"（需多次验证）
- `GUIDELINE` ❌ 对比日志写成流水账（应保留 A-F 六维结构）

# 第二篇：存储策略

> 提取完成后，决定内容写入哪个文件。上级政策/案例/学术直接写入对应 wiki 页面，内部文件需三层分流。

---

## 内部材料三层分流

| 层级 | 目标文件 | 内容范围 | 更新频率 |
|------|---------|---------|---------|
| **稳定层** | wiki/entities/机构-{名称}.md | 机构概况、定位、战略、文化、领导分工 | 低频，重大变化时更新 |
| **年度层** | wiki/entities/内部-年度工作要点-YYYY.md | 年度工作要点、任务指标、年度目标 | 每年一个文件 |
| **事件层** | wiki/entities/内部-重要会议与讲话.md | 会议讲话原文、年度成效数据、专项部署 | 每次重要事件后追加 |

### 分流判断

| 内容特征 | 归入层级 |
|---------|---------|
| 基本数据、概况、框架性表述 | 稳定层 |
| "2026年目标"等年度指标 | 年度层 |
| 会议讲话原文、成效数据 | 事件层 |
| 领导分工调整 | 稳定层 |

### 提取比例
- 稳定层：精简至 120 行以内
- 年度层：40% 原文引用
- 事件层：60% 原文引用（保留语境）

### 禁止事项
- ❌ 年度指标写入稳定层（造成过期数据）
- ❌ 会议讲话要点遗漏
- ❌ 稳定层超过 150 行
